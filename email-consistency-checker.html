檢查規則

單封MAIL (Single-email)

  • Approved Word（可選）：上載 `.docx` 後，自動讀第一個 TC／EN EDM 文案表；按 Email 語言比對 approved copy。另可加入 Tier／TC獎品／EN獎品表格驗證相應 Tier 獎品。無 Word 時不影響任何舊規則。
  • 語言連結：右上角「EN/繁體」link 指向嘅 *_T{tier}_*_(EN|TC).html，check 有無對應到你揀嘅 tier
  • 多餘空白：中文字之間嘅單一／連續空格（包括 &nbsp;、全形空格）、句末 &nbsp;、連續2+空格
  • 標點：中文段落用咗半形標點（,.!?()）、成對符號未閉合（「」『』（））
  • 稱謂：Chinese段落必須用「您」（避免用「你」）
  • 術語：Coupon統一用「電子現金券」，唔應該用「電子禮券」
  • 金額格式：HK$XX 之後接中文字時要加空格（正確：HK$50 電子現金券，錯：HK$100券）；前面接中文（例 獲享HK$50）係OK
  • HTML 雜訊：空 <a> tag、<u> 同 text-decoration:underline 混用

EDM (電郵版) 必備 vs 網頁版禁用

  • 📧 EDM 必須有：「在瀏覽器查看 / View in browser」連結（用 {{system.viewAsWebpageLink}}）、稱謂（{{lead.Salutation}} {{lead.Last Name}}）、積金易號碼 {{my.masked_empf_ID}}、退訂連結（Unsubscribe program + Unsubscribe all）
  • 🌐 網頁版禁止：以上EDM必備嘅嘢通通唔應該出現喺網頁版
  • Auto-detect：HTML含 {{system.*}} / {{lead.*}} template placeholder → email；否則 → web；可以喺file row 手動改

URL / 資料夾 支援

  • 可以直接貼URL加入check（會先 direct fetch，失敗fallback去corsproxy.io 或 allorigins）
  • 如果全部fallback都失敗（可能係CORS/network），可以喺browser打開個網頁 → View Page Source → Save As → drag入嚟
  • 完整網頁 folder 上載：下載成 HTML + 圖片folder，撳「📁 選整個資料夾」揀嗰個folder，tool會自動將圖片連 CSS 綁做 blob URL，preview 就可以正確顯示 & 比對圖片

字型/CSS 跨MAIL比對（Mobile + Desktop）

  • 會用 iframe render 每封MAIL喺 Mobile 375 同 Desktop 1200 兩個viewport下攞真正嘅 getComputedStyle（includes <style> block、@media query、inheritance — 唔止inline style）
  • Check keys: 文字對齊（置左/中/右） / font-weight（BOLD） / font-family / font-size / line-height / margin / color / font-style / text-decoration
  • 文字對齊用 bounding-box 視覺偵測（量度文字實際位置 vs 容器）— 唔理個置中係用 text-align、margin:auto 定 <td align> 做，都captured到。捉到「應該置左但置中」呢類問題
  • Majority vote：3+封MAIL之中1封唔一致 → 只 flag outlier；每個issue會標明係 📱 Mobile 定 💻 Desktop 出事
  • 捉到之前 inline-style only check 錯過嘅：<style> block 內定義嘅樣式、responsive layout差異、BOLD/置中mismatch

圖片跨MAIL比對

  • 比對 <img> 數量：3+封MAIL用 majority vote，少數outlier會flag「圖片數量同其他N封唔一致」
  • 比對 width / height：majority vote，尺寸outlier會flag
  • 跨 MAIL 圖片次序：以圖片最近嘅標題作 anchor；只有同一張圖被放到不同內容標題之下先提示。普通文案或金額不同唔會再當圖片移位。
  • 圖片對齊（置左/中/右）跨MAIL：用 bounding-box 量度每張圖喺容器內嘅水平位置，喺 Mobile + Desktop 兩個viewport分別check。majority vote：某封MAIL圖片置中但其他置左 → flag
  • 內容 Icon 方向一致性（單封MAIL）⭐：比較同一內容組內各 icon 嘅方向；全部置左或全部置中都視為正常，只有混合方向先警告。Banner / hero / CTA（闊圖）同頂部 logo 自動排除。
  • 圖片定位 debug：像素差只保留喺收合 debug 表，方便技術驗證量度；一般 QA 提示只列出每張 icon 嘅方向，唔顯示像素。
  • 用途：搵mobile版icon shift、被template漏走嘅圖、圖片size mismatch、圖片排位錯亂、圖片對齊唔一致

Viewport 切換

  • Preview toolbar：📱 375 / 📱 768 / 💻 Full — 切換iframe寬度，睇responsive layout差異

跨MAIL (Cross-email)

  • 用文字相似度做 fuzzy alignment：某封MAIL多咗/少咗一段唔會cascade shift位
  • 會遮走 tier 變數（HK$金額、tier名、asia miles數量）先比對
  • 一致 masked後所有MAIL都完全一樣
  • 只係變數 masked後一樣，raw text 只差 HK$金額 / tier名 — 正常
  • 真·不一致 masked後仍然唔同 — 要人手check
  • Tier專屬 只有某啲tier有嘅段落（例如T0多咗intro）— 正常
  • 字型/CSS：同一段paragraph嘅 font-family / font-size / line-height / margin 跨MAIL必須一致
